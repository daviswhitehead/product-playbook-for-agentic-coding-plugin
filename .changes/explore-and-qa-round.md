### Added
- **`/playbook:explore`: prototype first is now the default for UI or unclear work.** Five stages (frame → options → prototype → prd → plan), one per run, each stopping at a founder gate with rows in `decisions-queue.md` and `discovery/decisions.jsonl`: a grounding brief that cites every named action with file:line and labels anything new as NEW; 4–6 rendered options including wild ones, with real components at 320/390/768/1280 px before any layout pick; a single-file clickable prototype verified in a browser, every behavior rule drawn as a state; the PRD written from the prototype; then the plan, review board, tasks and REVIEW.md. A founder-persona review and a five-point pre-flight check (facts from code, one pattern, no visible caution added, elaborate needs a reason, written rules) run before anything reaches the founder. `--unattended` obeys a gate rule (ingest answers, stop with `NEXT: waiting on founder: …` while a blocking row is open, 48-hour defaults for reversible rows only), records main-agent and sub-agent tokens per stage, commits locally and never pushes or opens a PR. In the project that set this pattern the agent matched the founder on 7 of 7 scope calls but 3 of 11 visual ones; rendering the options is what made those misses cheap.
- **`/playbook:qa-round`.** Three agent passes before the founder sees anything (user journeys on a production build, adversarial, real device on the iOS Simulator at his device size), then `needs-founder.md`, a ≤10-step `testing-guide.md` in which every step was agent-tested first, and an after-deploy guide only after the deploy. His markup round feeds the taste ledger; any correction an earlier rule could have predicted becomes an edit to that rule in the same round. Templates in `resources/templates/qa-round/` (the old `qa-round.md` moved there as `findings.md`).
- **`scripts/check-testing-guide.sh`** (ported from chef-chopsky, made path-generic) and its 13-case test, now in CI. Against the real guide that prompted it, it fails on exactly the four after-deploy steps the founder could not run.
- **Templates:** `founder-taste.md` (principles with receipts, ledger schema and enums), `decision-log.md` (dated markup rounds), `spike.md`, `stage-summary.md`, and a prototype kit (`prototype/index.html`: state and width controls, URL params for screenshots, an event log).

### Changed
- **`/playbook:product-requirements`** routes UI and "not sure yet" work to explore, adds `--from-prototype <path>`, and runs one combined critique of the prototype and the PRD before the tech plan (decision B9, taken by the lead under founder delegation). The PRD template's bare Open Questions become **Decisions for the founder** (default, alternative, consequence, status `confirmed` with his quoted words or `assumed`), and the decision log is dated per round.
- **`/playbook:tech-plan`** accepts a prototype-derived PRD, asks for spikes first, and adds Step 3.6, the review board: every touched component tagged new / extended / reused / replaced, every rule's edge state drawn, open problems as options A–D.
- **`/playbook:close-project`** has a pre-flight: the latest `qa/round-<n>/` must be closed (findings settled, ledger rows appended, repeated corrections turned into rules, "Production, after deploy" filled). `verify-close-project.sh` asserts it (9 new cases, seen failing first).
- **`session-orientation.sh`** warns when the oldest uncommitted change is more than 24 h old (count and age only: file names never reach the agent's context, and paths are read NUL-separated as `./<path>` so hostile names can't inject options or instructions). One project went four days with nothing committed.
- **`resources/personas/founder.md`** loads the project's taste principles (never a whole ledger) and cites them by number. `/playbook:refine-doc` documents markup rounds; `/playbook:learnings` Step 10 counts founder agreement by category and appends ledger rows; `/playbook:work` Step 3.5 sends feature-sized taste work to explore; `/playbook:work-multiple` and `autonomous-execution` let unattended runs advance discovery to the next founder gate, delegate building from the first mockup round, and record tokens per stage. `/playbook:mockups` and `/playbook:design-critique` review options locally, never as a PR.
- **`ios-simulator-testing`**: iPad devices via `IOS_SIM_DEVICE`, `rect` / `contentOrigin` / `drag`, and the keyboard-reflow assertions (header inside `visualViewport`, `scrollY` 0, field above the keyboard), ported from the chef-chopsky harness.
